# 三维预演到 AI 视频的创作与验证流程

本地完善版本日期为 2026 年 10 月 11 日。此轮完善把原有的静态画面提示词导出改为视频调度导出，并增加真实生成记录入口。AI 模型运行仍在用户所选的平台完成；程序不自动调用 API，也不自动上传素材。

## 使用步骤

1. 在导演台摆放人物、道具和场景，为主体使用可辨识且互不重复的名称。
2. 设置人物路线、分段动作和停留动作，记录至少两个摄影机轨迹点。固定镜头可用两个位置相同的点。
3. 在“看成片”中检查整段动作、构图、跟踪主体、时间和画幅。避免只用导演视角判断最终画面。
4. 打开“导出 AI 提示词”，选择机位、工作流以及文字或参考视频方式。
5. 补充最终成片的内容、人物外观、场景、光线、风格和声音。人物名称应与三维主体对应；故事事件应与预演路线相容。
6. 检查分段提示词和“生成前检查”，下载 TXT 与 JSON 备份。
7. 使用参考模式时导出本机位 MP4，在生成平台上传，并将其绑定为运镜、构图、动作和节奏参考。Seedance 格式中的 `@视频1` 是待上传素材的占位符，实际编号应按平台上传顺序核对。这里没有上传任何视频。
8. 生成后保留结果视频，展开“生成验证与对比记录”，记录实际提交的提示词、模型及版本、种子（可获得时）、结果文件名、尝试次数、评分和失败现象。
9. 下载实验记录 JSON；与结果视频、参考视频、工程 JSON、提示词 JSON 一起保存到项目资料目录。

每个机位独立生成一条视频提示词。多机位导出不自动将它们排成一条影片，也不假设各机位的角色动作时间相互衔接。参考视频按钮只导出机位选择框对应的一个镜头。

## 提示词结构

参考模式先声明素材用途，避免把默认人偶、白模颜色或坐标辅助线复制到最终视频。随后依次给出概述、全局设定、时间轴、可选声音、连续性与排除项。

时间段取自现有镜头和人物运行时的到达与离开时间，保留小数秒，不强行取整或改动节奏。段内文字描述可观察的相机移动、主体动作、停留和画面方位。精确坐标不作为视频模型一定会执行的指令；数值数据保留在 JSON 中。

最终成片的光线来自用户设定或参考素材，不再根据编辑器天空亮度猜测“白天”或“夜晚”。未填写声音时不自动添加对白、音乐或音效。

## JSON 数据

顶层仍是镜头数组，保留 `shotId`、`shotName`、`promptText` 和 `structuredParams`，增加 `schemaVersion: 2`、`negativePrompt` 与 `warnings`。工程存储格式未改变。

| 字段 | 内容 |
| --- | --- |
| durationSeconds / aspectRatio | 机位时长、选定画幅和实际比例估算 |
| cinematography | 起始景别、角度、垂直 FOV、焦距估算 |
| timeline | 时间段、相机起止状态、主体动作和入画变化 |
| samples | 密集时间采样，保留曲线路线和中途入画主体 |
| sourceTracks | 原始镜头关键帧、人物路线与动作设置 |
| environment | 预演背景、地面与场景整体变换 |
| references | 素材角色与待上传状态 |
| continuity / negativeConstraints | 连续性和排除项 |
| quality | 入画方法、遮挡与骨骼采样边界 |

主体 `position` 是应用场景整体变换后的世界坐标；`rotationLocalRadians` 和 `scaleLocal` 是主体的局部变换。相机坐标采用现有播放计算结果。朝向由主体局部正 Z 方向估计，导入模型自身的朝向校正与骨骼动作应在参考视频中复核。

焦距以 24mm 垂直感光尺寸估算，标记为估算值，不代表真实摄影机标定结果。FOV 变化、跟踪身体部位、柔和跟随、防抖与原始轨道设置均在 JSON 中保留。

## 实际边界

入画判断使用近似包围球与视锥，在路线事件点、段内和约 0.25 秒间隔采样。它能排除明显在相机背后或远离画框的主体，也能保留中途入画的人物；不计算遮挡，不保证识别极短的一闪而过，不读取每个导入模型的精确几何轮廓。

身体部位跟踪的语义设置会进入提示词，但文字采样使用主体中心近似，不重放实际骨骼或逐帧阻尼。看成片和 MP4 使用原有真实渲染运行时，因此精细动作应优先使用参考视频。

提示词采样使用“看成片 FOV”，与参考视频导出的 FOV 覆盖设置一致，不使用独立监看小窗 FOV。选择固定“看成片 FOV”会覆盖路线点原有的视野变化，界面会提示这一点。

原有 MP4 导出使用浏览器实时录制，时间轴时长与文件实际时长可能有差异。此次浏览器实测设定为 5 秒，录制文件约 5.68 秒、1280×650，画幅跟随自动视口。生成实验应核对实际参考片长度；需要严格时长时，单独裁切或重定时后再上传。

创作设定和实验记录按导演台实例保存在浏览器，不上传服务器。清理浏览器数据或更换设备不会自动恢复；需要下载备份。实验记录保存文字与评分，不保存视频本体。

## 毕业设计验证方法

先选择四种小案例完成流程：推镜、人物跟拍、人物入画后停留挥手、双人调度。流程稳定后扩展到约十个镜头。不要把自动化程序测试当作 AI 生成效果实验。

同一镜头做三组：A 为手工普通文字提示词，B 为导演台分段提示词，C 为分段提示词加三维参考视频。保持创意内容、目标外观、模型版本、画幅和时长一致；平台支持种子时也固定种子。每组使用相同次数进行生成，保留全部失败结果，避免只挑最好的一次。

可以用 1 到 5 分评估运镜符合度、人物空间符合度和连续性。先写清评分标准，再由同一评估者或多位评估者独立评分；记录模型不能完成的事项。记录中的平均分和成功率只能来自真实生成数据，程序不会预填成功结论。

建议资料目录为：每个镜头一个子目录，分别保存工程、参考视频、A/B/C 提示词、各次生成结果、评分记录与失败截图。论文可讨论路线时间计算、动作采样、视野筛选、结构化导出和参考工作流的设计与局限。

## 开发贡献与成果材料

已有三维编辑器包含上游和社区贡献，来源见 `UPSTREAM.md`、`README.md` 与 `LICENSE`。本轮新增或重写的是视频提示词转换、导出面板、生成实验记录，以及对应测试。不能将整个既有三维编辑器描述为本轮从零完成，也不能仅凭代码量证明学校要求的个人工作量。

毕业设计说明应区分上游功能、本人设计和实现、AI 辅助开发环节，以及本人完成的测试、改进与真实生成实验。第三方模型素材的来源记录不等同于完整许可凭证，素材授权文件应另行归档。本轮没有补造授权、用户访谈、Windows 性能结果或 AI 生成实验数据。

提交前仍需完成实际生成实验、用户体验评估、学校要求的需求分析与系统架构材料、模型选择说明、毕业设计说明和 3 至 5 分钟展示视频。现有改动为这些材料提供可复现的软件功能，不等于已经完成全部学校交付物。
